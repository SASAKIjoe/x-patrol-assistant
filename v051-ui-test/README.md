## 一覧の使い方

1. 先に普段のV0.5またはV0.51からJSONバックアップを保存します。
2. 新しい試験URLを同じAndroid Chromeで開きます。別のPWAとしてインストールできます。
3. ウォッチの行をタップして詳細を開きます。初回の行は折りたたみ、メモ・リンク・詳しい日時は詳細内で確認します。
4. Xを開き、人間が実際に投稿を確認してから `✔` を記録します。誤って付けた場合は取り消せます。
5. `更新` で端末内の一覧を再集計し、絞り込みや最終確認が古い順・未確認順を更新します。

`✔` は人間による確認済みです。Xのいいね押下済みを意味しません。Xを開いただけでは記録せず、実際のいいねはX上で人間が操作します。確認を取り消すと現在の確認マーク・確認日時を解除し、過去の確認履歴は残します。

`−` は新着未判定です。現在はX APIに接続していないため、`更新` でXの新着投稿を取得しません。未確認や時間経過を `New` として表示しません。`New` は、将来、許可された正規ソースで実際の新着を検出・確認できる場合にだけ使う状態です。現在の試験では新着自動判定を提供しません。

## 保存と移行

試験版のIndexedDBは `xpatrol-v051-ui-test` です。初回に同じブラウザ・同じオリジンのV0.5保存データを読み取り専用で検証してコピーする設計です。コピー後は同期せず、旧版への書き戻し・削除・アップグレードは行いません。自動コピーできない場合は旧版のJSONを復元してください。

過去のV0.51データは、その版でJSONを保存し、新試験版のバックアップ復元から取り込みます。V0.51の保存領域を自動更新しません。ブラウザ・プロファイル・端末が異なる場合もJSONで移します。

JSONバックアップは互換性のためversion 5の形式を使います。復元ではプレビューを確認してから、この新試験版の現在のデータを置き換えます。先に現在のJSONを保存してください。破損データを自動初期化せず、復旧画面で元データを保存できる構成です。バックアップにはユーザー名・URL・メモ・確認履歴が含まれるので、公開リポジトリへアップロードしないでください。

選択タブ・絞り込み・並び順・展開状態・スクロール位置と候補行アンカーは、タブのsessionStorageと端末内localStorageへの補助保存で復帰する設計です。BFCache、外部Xアプリからの復帰、再読み込み、再起動を試験対象にします。Androidによるプロセス破棄・保存禁止・ブラウザデータ削除やOS側の挙動は実機で確認が必要です。保存情報自体を失った場合の完全復帰は保証できません。

## 共有とオフラインの留意点

静的ホスト向けの共有受信はGET形式です。初回や専用Service Workerが有効になる前は、共有文面を含むクエリがホストに届く可能性があります。既存のルートService Workerが最初のアクセスを制御する場合、その広いキャッシュ動作も残ります。受信後のURLから共有パラメータを除去しても、既に届いたリクエストを消すことはできません。必要に応じて投稿URLだけを手動入力してください。

専用Service Workerは同じ試験先の必要ファイルをまとめて保存し、共有クエリ・Xページ・バックアップをシェルキャッシュに追加しない設計です。最初にオンラインで準備してからオフライン起動を確認します。更新が待機中の場合は、この試験版の画面をすべて閉じて開き直します。
