# X巡回アシスタント V0.5

WORK_CODE: X-PATROL-005  
TASK_ID: X_PATROL_V05_ANDROID_SHARE_INBOX_RELEASE_V01  
公開予定URL（未検証）: https://sasakijoe.github.io/x-patrol-assistant/v05-test/

Androidで見つけたX投稿を共有して収集BOXにため、あとで選択して交流候補へ登録するPWAの完成候補です。X API・課金サービス・サーバー側データベースは使いません。投稿内容の自動取得、自動スクレイピング、自動いいね、常時クリップボード監視はありません。

**Android実機によるインストールとXアプリからの共有は未検証です。この項目はPASSではありません。** 公開・自動テスト・読戻しの実測結果は納品物のテスト結果およびEvidenceを参照してください。このREADME自体は試験成功の証拠ではありません。

本納品はアップロード可能な完成候補です。GitHubへの書込みは `403 Resource not accessible by integration` のため実行できませんでした。本版のGitHub公開、公開後ファイル読戻し、公開URLでの起動・保存・復元は未検証です。ローカル検証の成功を公開版の成功に読み替えません。

## 使い方

1. まず下記手順で公開してURLを確認します。その後AndroidのChromeで上記URLを開いてPWAをインストールします。具体的な手順・非対応時の代替手段は [Android.md](./Android.md) を参照してください。
2. X投稿の共有メニューから本アプリを選ぶと、検証した投稿URLを収集BOXへ保存します。続けてXに戻り、次の投稿を共有します。
3. 共有先が表示されない場合はXの「リンクをコピー」を使い、収集BOXの「リンクを貼り付けて収集する」に貼り付けます。複数URLをまとめて入力できます。
4. 収集BOXで投稿を選び、ジャンルを指定して「選択を候補へ登録」を押します。同じ投稿の重複を除き、同じユーザーの投稿は同じ候補にまとめます。
5. 「ジャンル」で名前・目標人数・検索語を管理し、「交流候補」で状態・メモ・巡回対象を管理します。1人を複数ジャンルに登録できます。
6. 「朝夜巡回」で朝または夜を選び、Xを開いて自分で確認したあと確認記録を付けます。確認履歴を同画面から閲覧できます。
7. 「保存・設定」からJSONバックアップをダウンロードします。別端末・別ブラウザにはJSONを移し、内容を確認して復元してください。

リンクの存在・投稿の公開状態・投稿者の実在はXへのアクセスで自動確認しません。URL形式の検証と正規化を行います。短縮URLは自動展開しないため、Xで正規の投稿リンクをコピーしてください。

`https://x.com/i/status/...` や `https://x.com/i/web/status/...` のように投稿者名がない投稿リンクもBOXに保留できます。候補へ登録する前にその投稿をXで自分で開いて投稿者のユーザー名を入力してください。自動取得で投稿者を推測しません。

## 保存と移行

データは同じオリジンの端末内ブラウザ保存領域に保存します。クラウド同期はありません。通常のタブとインストールしたPWAが同じ保存領域を共有するかは利用ブラウザによって異なるため、移動前にJSONを保存してください。プライベートモード、ブラウザのデータ削除、端末の容量不足では保存が維持できない場合があります。「端末への保存を保護」はブラウザへの永続化要求であり、バックアップの代わりにはなりません。

初回起動時、V0.5の保存データがない場合だけ、同じブラウザの既存V0.4→V0.3→V0.2の順にデータを検証してコピーします。旧版のファイル・保存キーは書き換えません。初回以降は旧版と同期しません。旧版を別ブラウザや別端末で使っている場合は、その版でJSONを出力してV0.5で復元します。壊れたデータを読み込んだ場合は自動初期化せず復旧画面に止まります。

復元は現在のV0.5データの置き換えです。先に現在のJSONを保存し、読み込むファイルのプレビューを確認してから確定してください。バックアップにはユーザー名・URL・ジャンル・メモ・履歴等が含まれます。公開GitHubリポジトリに自分のバックアップをアップロードしないでください。

## 共有の仕組みとプライバシー

manifestの `share_target` は `/x-patrol-assistant/v05-test/` へのGETです。Androidが渡す `title`・`text`・`url` をすべて確認し、投稿URLを抽出して検証します。共有本文全体を保存せず、受信後はブラウザ履歴の表示URLから共有クエリを消します。エラー時も共有本文のログを出しません。

GETのクエリには共有元が渡す投稿本文等が含まれ得ます。Service Workerが有効な通常の受信ではキャッシュのHTMLで処理しますが、初回・Service Workerが使えない場合等のGETはGitHub Pagesへの通常のリクエストとなり、URLクエリがホストに届く可能性があります。表示URLの除去は既に届いたリクエストやホストの記録を消す処理ではありません。機密の文章は共有せず、必要に応じて投稿URLだけを手動入力してください。

Chromeの公式仕様例はデータ変更を伴う共有でPOSTを推奨しています。本版はGitHub Pagesの静的配信で初回から使えることを優先し、GETの受信後に端末内で保存する構成を採用しています。POST用サーバーは設置しません。ファイル共有の受信は対象外です。[Chrome Web Share Targetの説明](https://developer.chrome.com/docs/capabilities/web-apis/web-share-target)

認証・Xログイン情報・パスワード・解析サービスはアプリで扱いません。Xへのリンクは利用者が押したときに開きます。外部ページには参照元を送らない設定です。GitHub・Chrome等のサービス自体による通常の配信やインストール処理は各サービスの仕様に従います。

## PWAと更新

manifestの `id`・`scope`・`start_url`・共有先はV0.5専用サブパスです。Service Workerのスコープも同じサブパスに限定します。V0.2／V0.3／V0.4のHTML・CSS・JavaScript・Service Workerは変更しません。

専用シェルキャッシュ `xp05-shell-*` には下記の必須11ファイルだけを先読みします。どれかが404等になれば新しいService Workerのインストールが失敗し、欠けた版をオフライン用に有効化しません。旧ルートのService Workerが削除対象とする `x-patrol-*` と異なる名前を使い、V0.5側も自分の接頭辞以外を削除しません。共有クエリをキャッシュキーにせず、Xのページ・ユーザーデータ・バックアップはシェルにキャッシュしません。

初回は通信中にページを開き、オフライン用の保存完了を待ってください。更新が待機中の場合はすべてのV0.5タブとアプリ画面を閉じて開き直します。配信担当者はランタイムファイルを変更するたびに `sw.js` のキャッシュ版を変更してから全ファイルを同時配信してください。公開後は必須ファイルのHTTPステータスとSHA256を再読出しで照合します。

## 公開

現在のGitHub Pages配信元設定は確定していません。リポジトリの `has_pages` 情報だけでは配信ブランチ・フォルダの確認にはなりません。既存設定を維持し、公開対象に `v05-test/` を追加してください。ルートの既存ファイル・旧版ディレクトリは変更しません。試験URLの応答と全必須ファイルの読戻しを確認するまで公開済み・PASSと判定しません。

アップロードの最短手順:

1. 納品のアップロード用ZIPを解凍します。`v05-test/` の中に上記11必須ファイルと2説明ファイルがあることを確認します。
2. GitHubの `SASAKIjoe/x-patrol-assistant` を開き、`main` ブランチのルートで「Add file」→「Upload files」を選びます。解凍した **`v05-test` フォルダごと** ドラッグします。既存の `v04-test` 等やルートの `index.html` は含めません。
3. アップロード先の表示がすべて `v05-test/...` であることを確認してコミットします。
4. リポジトリのSettings→Pagesで既存の配信元を確認します。`main` のルート配信ならそのままです。異なる配信元の場合は既存設定を変えず、その配信元にも同じ `v05-test/` を反映します。Actions配信の場合は既存の手順に従います。
5. Pagesのデプロイ成功を待って公開予定URLを開きます。起動だけで完了にせず、全必須ファイルのHTTP 200と納品SHA256を照合し、保存・再読込・復元・重複排除を確認します。その後Android実機試験を行います。

ローカル確認にはHTTPサーバーで配信してください。HTMLをファイルとして直接開く `file://` ではES Modules・Service Worker・PWAの確認ができません。実際のAndroid共有確認には有効なHTTPS公開URLからインストールしてください。
