## インストールと初回起動

1. AndroidのChromeで試験対象URLを開きます。X・YouTube内ブラウザから開いた場合は、Chromeのメニューで開き直します。
2. V0.7の画面と保存状態を確認します。通信できる状態でオフライン用シェルの準備が完了するまで待ちます。読み込み・保存エラーがある場合は先へ進めません。
3. Chromeメニューの「アプリをインストール」または「ホーム画面に追加」を選びます。表示される場合はアプリ内のインストールボタンも使用できます。文言と可否は端末・ブラウザによって異なります。
4. インストール完了後、ホーム画面・アプリ一覧から「SNS WATCH BOX V0.7」を起動します。Androidの設定→アプリに表示されるか確認し、インストール方式を記録します。
5. XまたはYouTubeの共有先一覧に「SNS WATCH BOX V0.7」または「SNS BOX 07」が表示されるか確認します。「その他」等の項目も確認します。

Chromeがショートカットを作った場合は、アイコンがあっても共有先機能を利用できないことがあります。共有先が出ない場合は、少し待ってから共有元のアプリとChromeを再起動して再確認します。再インストール前にはバックアップを保存します。成功しなければ機種・版・インストール方式・現象を記録し、「共有未対応・手動取込使用」と判定します。[GoogleのAndroidインストール説明](https://web.dev/learn/pwa/installation)

## X・YouTubeから連続収集

1. Xの投稿で共有を開き、外部アプリへの共有から本アプリを選びます。保存完了とBOXの増加を確認します。Androidの戻る操作やアプリ切替でXへ戻り、別の投稿を続けて共有します。
2. YouTubeの通常動画で「共有」から本アプリを選びます。YouTubeとして判別され、動画IDが保存されるか確認します。
3. YouTube Shortsで同じ操作を行います。次にURLに動画IDを含むライブ配信で同じ操作を行います。
4. 同じ動画の `youtu.be/動画ID`、`youtube.com/watch?v=動画ID`、`youtube.com/shorts/動画ID`、`youtube.com/live/動画ID` を手動で取り込み、BOXの同一動画が重複増加しないことを確認します。動画IDが同じならURL形式が違っても同一動画です。
5. XとYouTubeを交互に10件以上連続共有し、各件の受信結果・開始件数・終了件数を記録します。起動中の共有と、アプリを終了してからの共有を分けて試験します。

共有元によってURLが `url`、`text`、`title` のいずれに入るかが変わります。動画タイトル・本文とURLが混ざる場合も試験します。動画URLからチャンネル名やチャンネルIDを推測しません。確認できないチャンネル情報は利用者が実際の動画画面で確認して手動入力します。`@handle/live` 等、動画IDのない配信先は動画IDを補完せず、表示された案内に従って実際の動画URLまたはチャンネル情報を手動登録します。

## 一括登録・ウォッチ管理

1. BOXでXとYouTubeの複数件を選び、ジャンルを指定して一括登録します。選択分だけが処理され、既存候補・ウォッチが重複しないことを確認します。
2. YouTubeの動画ウォッチと交流候補を確認し、必要な公開チャンネル名・チャンネルURL等を手動で登録します。チャンネル不明の動画が別人に勝手にひも付かないことを確認します。
3. ジャンルを追加し、名前と目標人数を変更します。ジャンル別の候補人数・目標人数を確認します。使用中ジャンルを削除しても候補・動画・履歴が消えないことを確認します。
4. 朝の巡回と夜の巡回をそれぞれ実行し、確認済み操作を行います。日付・朝夜・対象が履歴に残り、再起動後も保持されるか確認します。外部SNSの閲覧や交流は利用者が行います。

## オフライン・保存・復元

1. オンラインで一度起動してから機内モードにします。V0.7を終了して開き直し、画面と保存済みデータが表示されるか確認します。既知の共有URLを手動取込して保存します。オフラインでX・YouTube動画そのものを閲覧できるとは限りません。
2. 再度オンラインに戻し、アプリ終了・Chrome終了・端末再起動の各段階で件数と履歴を確認します。
3. JSONバックアップを保存し、Androidのファイルアプリで実体を確認します。バックアップには利用者が登録したURL・メモ・履歴が含まれるため、公開リポジトリへはアップロードしません。
4. 試験専用の別プロファイル等で復元し、BOX・候補・ウォッチ・ジャンル・目標・履歴が一致するか確認します。
5. 壊れたJSON・他形式・想定上限を超える入力を使い、エラー時に既存データが維持されるか確認します。正常JSONの復元で置換される範囲は画面の案内を確認します。
6. 旧版バックアップをV0.7へ取り込み、旧版へ戻って元のデータが保持されているか確認します。V0.5・V0.6の保存領域をV0.7から書き換えたり削除したりしません。

## 共有の制限と手動取込

共有先に出ない場合や共有元が対応しない場合は、X・YouTubeの「リンクをコピー」を使い、本アプリの入力欄に利用者自身が貼り付けて追加します。アプリはクリップボードを自動取得しません。

静的なGitHub Pagesで動作するため、本版はGET共有を使用します。共有済みの内容はURLのクエリとして渡されます。Service Worker制御下ではクエリを含むURLをネットワーク送信・キャッシュ保存せず、画面が受信内容を処理します。ただし初回・Worker未制御・無効時等は共有クエリがホスティング側へ届く可能性があります。共有元が付ける本文に機密情報や認証情報を含めず、必要なら公開の動画・投稿URLだけを手動入力してください。共有本文はチャンネル情報を補完する根拠にはしません。[Chrome Web Share Target説明](https://developer.chrome.com/docs/capabilities/web-apis/web-share-target)
